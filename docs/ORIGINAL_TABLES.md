# Historical code tables and generator revisions

[ORIGINAL_TABLE_INVENTORY.json](ORIGINAL_TABLE_INVENTORY.json) records each saved table's hash, variable names, array shapes/types, and selected code-count metadata. These tables are research artifacts from different revisions. They must not be treated as outputs regenerated by the exact currently recovered script.

## Source behavior versus saved dictionaries

- The active `genNoise.m` creates fixed-width variants from a bit flip, a bit slip with boundary fill, and binary insertion followed by truncation. The caller considers rotated versions for cyclic phase handling. This is a bounded model, not arbitrary edit-error correction.
- The recovered `genCodesCyclic.m` allocates a dictionary of length `2^n` and writes `cnt` (one-based code-list position). It currently comments out its MAT save and writes `A{n}.codes` instead.
- The actual saved `CodeCyclicN.mat` files have dictionary length `2^(n+1)` and nonzero values equal to the **raw numeric code plus one**. Zero is the unknown/unassigned sentinel. `CodeNonCyclicN.mat` uses the same raw-code-plus-one convention.
- Therefore MATLAB array position and the stored dictionary value are different concepts. A consumer mapping into ordered beacon IDs must translate raw numeric code values through that file's `codes` list. It must not interpret a dictionary value directly as a list index.

For example, `CodeCyclic3.mat` stores `codes = [0, 7]` and a dictionary with 16 entries, including stored value 8 for raw code 7. `CodeCyclic8.mat` stores `[0, 7, 51, 85, 127]` and a dictionary with 512 entries.

Most saved cyclic tables include zero, but this is not universal: `CodeCyclic10.mat` stores `[1, 15, 83, 127, 439]`. The filename's nominal bit length also does not imply that the all-ones value is present. Small table contents, constant-code policy, generation order, and dictionary semantics must be checked explicitly.

`21codes.mat` and `FullyRobustCyclicCodes.mat` contain separate indexed cell/struct collections of code lists. Their counts differ from individual MAT dictionaries. The three DAT files are binary-text export experiments, not interchangeable serialized dictionary arrays.

## New implementation boundary

The new `updated/` implementation defines its own ordered beacon IDs and an explicit nonconstant-code policy. Any compatibility/parity checks must name their exact historical fixtures and translation rules. Passing a selected table fixture does not establish regeneration of every archived table, reproduction of MATLAB results, or a camera/hardware tracking result.

All originals remain unchanged. The source manifest links 19 exact cyclic-table matches to the separately published CoBe archive.
